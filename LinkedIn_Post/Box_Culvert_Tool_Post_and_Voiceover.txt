BOX CULVERT AUTOMATION - LINKEDIN POST + VIDEO VOICEOVER
========================================================

LINKEDIN POST (plain text, paste as is)
---------------------------------------

Every box culvert I model in STAAD starts the same way: draw the frame, work out the spring stiffness node by node, then type in the same set of load cases again. So I started automating it.

It's a Python tool that drives STAAD.Pro through OpenSTAAD. Into a blank STAAD file, it builds the single-cell frame and sections, adds compression-only soil springs (ks = 40 x FOS x SBC, with the outer half of each wall carried by the end spring), and applies dead load, SIDL, earth pressure, live load surcharge, braking and water inside the cell. A second script writes the load calculation as an Excel sheet with live formulas, and every key value is cross-checked against what went into STAAD.

The most useful habit it taught me: read back what the software actually stored. On the first run every support came out with its releases inverted. The documentation described one convention, the model used the opposite, and only the read-back check caught it.

I built it with Claude Code as my coding partner. The engineering decisions and every check in STAAD were mine.

Next: IRC vehicle loads, load combinations, and joining both scripts into one tool with a proper input window.

If you automate STAAD, how do you check what the model actually stored?
